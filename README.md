# ChatMonitor

无人值守刷新聊天工具群动态：周期性模拟真人点击指定群、指定人的消息并滚动阅读。
测试客户端为微信 Mac 端，正式目标为 Telegram Desktop（配置可切换任意应用）。

**仅限个人自用。** 账号自动化可能违反聊天工具服务条款，使用风险自负。

## 工作原理

```
定时循环（按 idleSeconds 节奏切换目标）
 ├─ 锁屏检测      → 锁屏中则跳过本轮
 ├─ 进程检测      → 目标应用未运行则跳过
 ├─ 真人避让      → 鼠标或键盘闲置 idleSeconds 秒才接管；执行中用户有任何输入立即中止让出
 └─ 单轮任务
     ├─ 激活目标应用
     ├─ 全屏截图 + macOS Vision OCR 识别文字
     ├─ targets 轮流切换（round-robin）→ 左侧区域找关键字 → 拟人点击（贝塞尔轨迹 + 抖动）
     ├─ 可选：右侧消息区找 personKeyword 的消息 → 拟人点击
     └─ 拟人滚动（分段变速 + 随机停顿 + 偶尔回看）
```

技术栈：Java 21（JDK 自带 `Robot`/`ProcessHandle`，零第三方依赖）+
Swift 编译的 `ocr_helper`（Vision OCR / 窗口查询 / 锁屏与权限检测）。

## 首次使用

### 1. 构建

```bash
./build.sh
```

### 2. 授予系统权限（各一次）

程序启动时会检测并自动打开对应设置面板，把运行程序的**终端应用**（如 Terminal / iTerm2 / IDEA）勾选上：

- **辅助功能**（系统设置 → 隐私与安全性 → 辅助功能）：否则鼠标移动/点击/滚动会被系统静默拦截
- **屏幕录制**（系统设置 → 隐私与安全性 → 屏幕录制）：否则无法截图 OCR
- **输入监控**（系统设置 → 隐私与安全性 → 输入监控）：用于检测键盘活动（防止打字时被误判为闲置）。未授权则退化为仅鼠标检测

授权后**无需重启程序**，下一轮任务自动生效。

### 3. 编辑配置

```bash
vim config.properties
```

关键字段：`processName`（进程名）、`targets`（逗号分隔的群聊/联系人列表，每轮轮流切换下一个）、
`personKeyword`（会话内要点的人，留空则进入会话后直接滚动）、
`idleSeconds`（真人闲置该秒数后接管，并以此节奏切换目标）。
文件修改后约 30 秒内自动热加载。

### 4. 启动

```bash
./run.sh        # 后台运行，日志 chatmonitor.log
tail -f chatmonitor.log
kill $(pgrep -f com.chatmonitor.Main)   # 停止
```

## 故障排查

| 现象 | 原因/处理 |
|------|-----------|
| 日志提示缺权限 | 按第 2 步授权，无需重启 |
| OCR 识别不到文字 | 确认屏幕录制权限；确认目标窗口未被遮挡 |
| 点击位置偏移 | Telegram 窗口大小/DPI 变化，重启程序或调整窗口后重试 |
| 找不到目标关键字 | 确认 `config.properties` 关键字与界面文字一致（支持部分匹配，忽略空格）；目标需在当前屏幕可见（主显示器） |
| 一直等待闲置 | 属预期行为：真人操作（鼠标/键盘）期间程序不抢，停止操作 idleSeconds 秒后自动接管 |
| 打字时仍被抢操作 | 未授权「输入监控」权限，键盘检测退化为仅鼠标检测 |
| 连续失败后静默 | 属预期行为：连续失败 3 次进入随机退避（60~300 秒）自愈 |
